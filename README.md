# Інформаційна система керування заявками на вивезення відходів

Курсова робота з дисципліни «Кросплатформене програмування», варіант №7
(студент Демусенко Р. І., група 202-ТН, керівник Заїка С. О.).

Система допомагає диспетчеру комунальної служби обробляти заявки на вивезення відходів із
контейнерних майданчиків. Основні сутності: **контейнерний майданчик**, **заявка**, **транспортний засіб**
і **виїзд**. Для кожної заявки сервер сам розраховує інтегральний показник терміновості
I = 0,40·F1 + 0,35·F2 + 0,25·F3 (F1 — рівень заповнення, F2 — санітарний ризик, F3 — прострочення,
усі фактори в межах 0–100) і контролює чотиристанний життєвий цикл
**СТВОРЕНО → ЗАПЛАНОВАНО → ВИКОНУЄТЬСЯ → ВИКОНАНО**. Через JavaFX-клієнт можна переглядати дані,
виконувати CRUD, перераховувати показник, змінювати стан заявок та імпортувати майданчики з CSV-файла.

Маршрут запиту: JavaFX → HTTP-клієнт → HTTP/JSON → Servlet → Service → DAO → JDBC → MySQL.

## Технології

| Технологія | Призначення |
|------------|-------------|
| Java 21, Maven | мова та складання двох модулів (`server`, `client`) |
| Servlet API 4.0.1, Apache Tomcat 9.x | серверна частина у вигляді WAR (пакети `javax.servlet`) |
| JDBC, MySQL (XAMPP), MySQL Connector/J 9.7.0 | зберігання даних |
| Jackson 2.17.2 | JSON у сервері та клієнті |
| JavaFX 21.0.5 | графічний інтерфейс; `javafx.concurrent.Task` — фоновий імпорт CSV |
| JUnit 5.11.4 (Jupiter) | модульні тести сервера |
| Git, GitHub | контроль версій |

Клієнт не містить SQL і не підключається до MySQL: усі дані проходять через сервер.

## Підготовка MySQL

1. Запустити MySQL (XAMPP Control Panel → MySQL → Start).
2. Відкрити `http://localhost/phpmyadmin` → **Імпорт** → вибрати `database.sql` → **Вперед**.
   Скрипт видаляє й заново створює базу `waste_requests`, тому виконуйте його лише на тестовому сервері.
3. Параметри підключення (`localhost:3306`, користувач `root` без пароля) задано в
   `server/src/main/java/ua/edu/nupp/kpp/server/DBUtil.java`; за потреби змініть їх там.

## Складання й запуск сервера

```
cd server
mvn clean package
```

Буде створено `server/target/kpp-server.war`. Скопіюйте його в каталог `webapps` встановленого Tomcat 9.x
і запустіть Tomcat. Перевірка в браузері:

- `http://localhost:8080/kpp-server/ping` — сервер працює;
- `http://localhost:8080/kpp-server/sites` — JSON зі списком майданчиків.

## Запуск JavaFX-клієнта

Клієнт запускають із каталогу `client` (від нього обчислюються відносні шляхи до CSV):

```
cd client
mvn javafx:run
```

Адреса сервера за замовчуванням — `http://localhost:8080/kpp-server`; її можна змінити системною
властивістю `kpp.server.url`.

## Тести JUnit 5

```
cd server
mvn clean test
```

Тести перевіряють розрахунок F1–F3 та інтегрального показника, відхилення недопустимих значень,
дозволені й заборонені переходи життєвого циклу та валідацію сутностей. Вони не потребують
запущених MySQL, Tomcat і JavaFX. Команда `mvn clean package` також запускає тести перед
створенням WAR.

## CSV-імпорт майданчиків

Імпорт виконується у вкладці **Майданчики**: вкажіть шлях до файла (за замовчуванням
`sample-data/container_sites.csv`, кнопка **Огляд…** відкриває вибір файла) і натисніть
**Імпортувати CSV**. Читання файла й передавання записів на сервер працюють у фоновому потоці
(`ImportSitesTask`), тому вікно не блокується; поки імпорт триває, повторний запуск недоступний,
хід виконання показує `ProgressBar`, а після завершення таблиця оновлюється з сервера.

Формат файла: UTF-8, роздільник `;`, перший рядок — заголовок, 9 стовпців, десяткова крапка:

```
code;name;address;district;waste_type;container_count;capacity_l;fill_level;sanitary_risk
CS-006;Майданчик «Лікарня»;вул. Шевченка, 23;Шевченківський;MIXED;4;4400;60.0;85.0
```

Клієнт перевіряє формат: заголовок, кількість полів, порожні значення, числа. Рядок із помилкою формату
пропускається з попередженням у журналі. Предметні правила (діапазон 0–100, унікальність коду)
перевіряє сервер; запис, який він відхилив, також пропускається. Якщо сервер недоступний,
імпорт завершується помилкою, а записи, які сервер уже прийняв, залишаються в базі.
Журнал імпорту (початок, кількість імпортованих і пропущених рядків, причини) виводиться в консоль
через `java.util.logging`.

Файли в `client/sample-data`:

| Файл | Призначення |
|------|-------------|
| `container_sites.csv` | 6 коректних майданчиків (CS-005…CS-010) для чистої бази |
| `container_sites_test.csv` | 3 коректні рядки та 5 помилкових (формат, діапазон, дублікат) |
| `container_sites_bad_header.csv` | файл із неправильним заголовком: імпорт відхиляється до першого запиту |

Повторний імпорт того самого файла не створює дублікатів: сервер відхиляє записи з уже наявним кодом.

## HTTP-маршрути

| URL | Servlet | Призначення |
|-----|---------|-------------|
| `/ping` | PingServlet | перевірка доступності сервера |
| `/sites` | ContainerSiteServlet | контейнерні майданчики |
| `/requests` | WasteRequestServlet | заявки, перерахунок показника, зміна стану |
| `/vehicles` | VehicleServlet | транспортні засоби |
| `/trips` | TripServlet | виїзди |

GET повертає дані у форматі JSON. Зміни виконує POST (`application/x-www-form-urlencoded`)
із параметром `action`: `add`, `update`, `delete`; для заявок також `recalculate` і `transition`.
Помилки повертаються у вигляді `{"error": "..."}` з кодом 400 (вхідні та предметні помилки) або 500.
